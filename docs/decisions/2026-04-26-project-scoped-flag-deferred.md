# החלטה: דחיית `projects.uses_new_master_data` ל-Phase 2

**תאריך**: 26.04.2026  
**סטטוס**: ❶ אומצה  
**הקשר**: תוכנית הפצה ב-`docs/architecture/rollout-plan-master-data.md` — Stage 3 Pilot

---

## הקשר

ה-Focus Mode הנוכחי הוא **דגל סביבה גלובלי** (`NEXT_PUBLIC_FOCUS_MODE`). אין דרך נקייה להפעיל את המערכת החדשה רק על פרויקט אחד ופרויקטים אחרים על המערכת הישנה. זה יוצר חשש שאם הפיילוט נתקע באמצע — אין rollback ברמת פרויקט.

## אלטרנטיבות שנשקלו

### A. הוספת `projects.uses_new_master_data boolean default false`
**יתרונות**:
- Rollback ברמת פרויקט.
- כל מסכי הרכש בודקים את הדגל לפני בחירת UI.
- הפצה הדרגתית: אפשר להעלות פרויקט נוסף לפיילוט בלי קוד חדש.

**חסרונות**:
- **כל מסך רכש צריך להוסיף בדיקת flag** — עשרות נקודות עריכה.
- מורכבות קוגניטיבית: מהנדס שעובר בין פרויקטים רואה UI שונה.
- Race conditions אפשריות בעת מעבר מצב.

### B. השארת המצב הנוכחי (env flag בלבד) ✅ נבחרה
**יתרונות**:
- אפס שינויים בקוד.
- ה-Focus Mode הוא רק ויזואלי (סינון תפריט) — לא משנה התנהגות מודולים.
- כל הקוד כבר משתמש ב-`erp_md_items` הקנוני (אודיט אישר 26.04.2026).

**חסרונות**:
- אם הפיילוט נתקע — `rollback` = "להפסיק להפיק PO דרך המערכת" + תהליך ידני זמני.
- המנהל צריך להחזיק שני workflows במקביל למשך הפיילוט.

## הכרעה

**B. השארת המצב הנוכחי**.

### נימוקים

1. **המערכת החדשה והישנה כבר חולקות מקור נתונים יחיד** — `erp_md_items`. הפיילוט אינו "מערכת חדשה לעומת ישנה" אלא "אופן שימוש חדש באותם נתונים".

2. **ה-Focus Mode מטפל ב-UX**, לא בקוד. כשהוא דלוק — מהנדס לא רואה את המערכת המלאה. כשהוא כבוי — רואה הכל. אין פיצול קוד מאחורי הקלעים.

3. **הפיילוט הראשון יהיה צמוד-ניהולי** — מנהל הפרויקט יודע שהוא בפיילוט. אין צורך ב-flag DB; הוא פשוט "לא נכנס למערכת אם זה לא הפרויקט שלו".

4. **עלות-תועלת**: בניית flag-per-project בכל מסכי הרכש = 1-2 ימי עבודה. החזר השקעה: רק אם הפיילוט נתקע. ואם הפיילוט נתקע, יש לנו בעיה גדולה יותר שלא תיפתר ע״י דגל.

## תנאים לשינוי ההכרעה (Re-open Triggers)

החלטה זו תיפתח מחדש אם:

1. **הפיילוט הראשון מצליח** ועוברים ל-2-3 פרויקטים במקביל. אז דגל-DB הופך לחיוני.
2. **מודול שוקל לשנות התנהגות** (לא רק UI) על-בסיס המעבר — אז צריך להבחין על-פי פרויקט.
3. **דרישה ספציפית מלקוח** ליכולת A/B per-project.

## תיעוד הקוד הנוכחי

```ts
// lib/marker-ofek/focus-mode.ts
export function isFocusModeActive(): boolean {
  return process.env.NEXT_PUBLIC_FOCUS_MODE === "items"
}
```

זוהי הנקודה היחידה שבודקת focus mode. אין reads מ-`projects` או מ-`feature_flags`.
